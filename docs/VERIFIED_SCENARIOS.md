# 已验证场景与排障经验

以下整理开发和部署过程中的历史验证。主机名、地址、设备标识、账号和原始 UI 内容均省略或替换为文档示例，不附带真实配置、日志、抓包、会话或凭据。部分验证发生在早期版本；当前配置能力以源码、CI 和安装手册为准。

## 验证等级

- **真实手机验证**：实际安卓设备、视频或操作参与测试；仍需说明客户端位于 LAN 还是外网。
- **真实通道与模拟视频**：使用浏览器/媒体通道和模拟 H.264，确认协议/切换行为，不代表测试了真实手机操作。部分故障是人工注入的。
- **模拟测试**：模拟浏览器服务/设备或只检查配置，可验证程序策略，不能证明公网可达。
- **用户外网反馈**：操作者从外网提供的现象/诊断，不等于项目可复现每一种受限环境。
- **配置可选、未实测**：架构或参数允许，但没有对应端到端实测证据。

## 成功记录与适用条件

| 场景 | 验证等级与观察 | 能说明什么 |
| --- | --- | --- |
| Linux USB Docker 控制台 | 真实手机验证：H.264 解码、独立页面控制令牌、持久 Cookie、容器重启后重新连接和保留 ADB 授权均通过 | 私有密码/状态/ADB home 挂载的部署方式可工作；不代表其他 CPU、NAS 或设备自动兼容 |
| 家宽 HTTPS 反代、非标准端口、`/phone/` 子路径 | 真实手机验证：登录、Secure/HttpOnly/Strict Cookie、资源/SDK 链接、事件/控制 WebSocket、页面接管/重连、错误 Origin 拒绝及重启后会话通过；媒体客户端位于 LAN | 公网网页入口和子路径可以工作；LAN 客户端媒体成功不能证明任意外网 WebRTC 打洞成功 |
| Cloudflare Tunnel、独立子域名 | 真实手机验证：公网 HTTPS 页面入口、登录和控制链路通过，LAN 客户端能解码真实手机视频 | Tunnel 可以承载网页/控制；不能把该 LAN 媒体结果解释为 Tunnel 转发了 WebRTC |
| 自建 coturn TLS 非标准端口 | 真实手机验证记录中，双方取得 relay 候选、选中候选对成功，真实手机帧被解码；另有普通外网桌面 Chromium 用户反馈成功 | 自建 TURN 的证书/分配/媒体链路存在成功路径；并不保证所有云端浏览器允许该协议或端口 |
| Cloudflare TURN | 专用 key 的 API/短期凭据/relay 分配测试通过；真实 TURN 通道配合模拟 H.264 的切换测试通过；另有云端浏览器用户反馈替换后可用 | Cloudflare 可以作为独立的次优中继；不能仅凭本地分配成功证明每个远端 agent 已收到真实手机帧 |
| WSS 备用 | 用户报告：某受限云端浏览器在 TURN 失败后可连接 WSS，但早期串行等待较长。模拟 H.264 通过浏览器 WSS 解码/绘制，暂停、恢复、重连测试通过 | 同源 HTTP/WebSocket 可提供另一条媒体路径；具体真实手机公网流畅度仍按实际客户端检查 |
| 通知栏、快捷设置、保持亮屏、Unicode 文本 | 真实手机验证：打开面板、临时电源设置恢复、无障碍文本 Unicode 回读通过；UHID 注册也通过 | 这些系统能力在已测设备上可用；原始硬件 ASCII 上屏在某第三方 IME 场景未被确认，不能宣称绕过所有输入法 |
| 真实 HTML 手机输入框 | 模拟设备浏览器测试：`fill`、逐字输入、中文/emoji、空文本、Enter 提交、焦点保护和结果验证通过；视频表面本身不能 `fill` | DOM 型智能体应操作实际 textbox；不能据此保证每个安卓 WebView 都支持文本写入 |
| 并行择优与重连 | 模拟视频和故障/延迟注入测试：先显示较早就绪通道，随后升级、关闭低优先级；断连时并行重试；手动只走选中通道 | 程序策略已验证；新的网络环境仍需证明每条路径的真实可达性 |

此外，公共默认配置、两种网页入口与各视频方案的组合由 `npm run check:compose` 自动解析检查，禁用 WebRTC 后不会要求 TURN 密钥。配置解析成功不创建容器、手机连接或公网流量。

## 失败记录同样有参考价值

| 现象 | 结论与应对 |
| --- | --- |
| STUN 返回的地址属于代理/VPN 出口，而非预期家宽出口 | 检查真实网络路径和 UDP 分流；不能把任意出口地址写进公网候选。修正后取得预期出口，仍不保证远端能打洞 |
| 服务端有 srflx 候选，远端只有本地主机候选，始终没有选中候选对 | 不能根据“STUN 成功”判定连接成功。检查浏览器网络限制、NAT/防火墙；再选择 TURN 或 WSS |
| 一个云端浏览器连接自建 TLS 端点被拒绝，另一个 HTTPS 可以到达但 TURN Allocate 超时 | HTTPS 可达、TCP/TLS 可达和 TURN 协议可用是不同证据。根据真实候选/错误/帧诊断判断，不用网页请求代替 TURN 测试 |
| 某云端浏览器访问 Cloudflare HTTPS 正常，但 Cloudflare TURN Allocate 同样超时、无 relay 候选 | 公网供应商端口 443 也不保证被浏览器环境允许。WSS 可作为另一条通道，不把增加等待时间当作保证 |
| 硬件键盘已注册，但输入仍受第三方 IME 解释或未能确认 ASCII 上屏 | UHID 可用不等于普通文本必定按字面上屏；优先使用受确认的文本替换/回读路线 |
| 页面或容器健康，画面停住/暂停 | 检查屏幕/锁屏、暂停原因、末帧年龄和解码帧数。视频与 UI 树新鲜度分别判断 |

## 尚不能称为已跑通的场景

无线 ADB 的所有设备组合、macOS 作为原生控制台主机、原生 Windows、ARM/所有 NAS、IPv6-only 媒体、任意 VPS/路由器以及所有浏览器，都没有被上述记录覆盖。macOS 桌面浏览器作为外网客户端成功，不代表 macOS 服务端部署已实测。VPS coturn 是可配置拓扑，不能仅凭家宽 coturn 成功宣称它也经过验证。

## 复现自己的环境

从[部署场景指南](DEPLOYMENT_SCENARIOS.md)选择条件和示例，在自己的客户端网络逐层确认：网页鉴权 → WebSocket 控制 → 候选/选中路径 → 实际渲染帧 → 无害手机操作 → 重启/断连恢复。

分享诊断时可保留 provider、候选类型、协议、状态、错误码、帧数、暂停原因及观察到的动作结果。公网/内网地址按角色替换，清除账户、Cookie、CSRF/页面令牌、长期或短期 TURN 凭据、设备序列号、输入内容、脚本正文和个人截图。不要直接把原始私有证据目录提交到仓库。

这里的脱敏用于公开文档或公开问题报告，不改变部署者自己的私有请求审计；后者仍记录实际客户端 IP、浏览器标识和请求/会话元数据。
