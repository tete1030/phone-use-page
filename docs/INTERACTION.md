# 点击方式与受保护画面

## 坐标触摸与元素定位

元素点击先确认目标身份、可用性和屏幕内边界，再执行动作。坐标触摸通过 scrcpy 发送按下、抬起事件。UI Automator 的元素定位点击则由其定位器查找控件并执行点击；其常规 `click()` 最终也发送坐标触摸，不能把这条路径标为无障碍节点的 `ACTION_CLICK`。

真实的节点动作是 `AccessibilityNodeInfo.performAction(ACTION_CLICK)` 等接口，与上述两条触摸路径不同。当前上游 UI Automator 接口没有供本项目直接使用的通用节点动作入口，需要另外扩展 Android 端能力。

触摸注入不能保证与物理手指无法区分。落点偏移只改变点击位置，不证明能够避免应用风控。轨迹合成（见“手势的合成方式”）同样只改变运动形状，不改变“事件由注入产生”这一事实。节点位于屏幕范围内，也不代表没有被其他窗口遮挡。

非 `clickable` 的文字或描述标签，可以由最近的有效可点击祖先承接 `click()`。先唯一匹配原标签，再检查父链、包名、边界、可用性与当前窗口；落点留在原标签区域，不使用整行或大容器的中心。缺失父链、独立控件遮挡、窗口变化或无法唯一确认原生控件时拒绝。节点原始 `clickable` 属性保持不变，网页按钮显示“点击所在行”；回执用 `sourceTarget`、`actionTarget` 区分匹配目标与承接目标。长按、聚焦、开关及文字替换不继承祖先能力。

选择器的 `text` 与 `description` 是不同的精确字段；网页搜索可以同时检索文字、描述、显示 ID、资源 ID、类名、包名与“可编辑”等状态。搜索覆盖原始节点，包括精简模式隐藏的重复文字，保留父链上下文；“筛选中”与清除按钮只在存在关键词时显示，不改变 JS 选择器的唯一匹配规则。

## 观察、详情与动作结果

“立即读取”与 `device.observe()` 请求新采集。如果已有读取在进行，等待其结束后再采集；手机动作后的观察也必须在动作完成后开始。`snapshotId` 表示节点内容版本，内容不变时 ID 不变；每次成功采集的 `captureSeq` 仍增加。前端按采集顺序和状态版本接受消息，迟到的刷新响应不能覆盖新的观察，返回的观察不会随后台状态继续改变。

正常页面不展示采集序号或重复的读取状态。读取时原按钮显示“读取中”；采集失败或十五秒没有成功观察时，元素区显示过期提示并暂停节点动作与文字读写，直接画面操作仍由手机电源和控制通道状态判断。UI 根不可读与 ADB/视频断开分别处理。

切换窗口、节点消失或位置变化后，当前节点检查清空。“查看完整属性”在只读详情中展示采集时的节点和来源窗口，可复制 JSON，不写入动作时间线。设备信息与原始键盘、剪贴板、额外手势同样按需打开；更多工具使用可关闭的对话框，打开时底层工作区不可交互，关闭后恢复。

时间线为每个完整屏幕手势保留一条确认或拒绝记录，移动样本不逐帧显示。脚本进度更新同一条任务记录，简短返回值、发送/验证状态和错误直接显示，完整结果与日志在展开详情后生成，关闭后移除；历史脚本中的观察属于运行时快照。`verification=not_verified` 始终表示控制事件已发送而效果未验证。脚本停止后，控制释放完成前不会接受新的手机动作；断连后不重放旧手势或续跑脚本。

SDK 错误提供稳定的 `code`。已发送而无法确认的动作还提供 `execution`、`verification`，脚本可以读取这些字段，不必解析中文报错：

```js
try {
  await device.element({resourceId: "com.example.app:id/search"}).setText("文本");
} catch (error) {
  return {code: error.code, execution: error.execution, verification: error.verification};
}
```

## 随机落点

元素点击、长按，以及需要改变状态的开关点击，默认开启随机落点。界面元素区域的“随机落点”复选框可以关闭它，设置保存在当前浏览器中。执行 JS 时保存该设置作为本次任务的默认值；任务开始后再修改复选框，不会改变运行中任务的默认值。

落点位于目标与手机屏幕相交区域的中心附近，每个方向的偏移最多为 5 个手机像素，且不超过该方向有效区域尺寸的 10%。小于 10 像素的方向不偏移。选定的落点在按下和抬起时保持一致，长按不会变成拖动。关闭偏移时使用中心点。

以下 JS 参数可以覆盖任务默认值：

```js
await device.element({text: "目标按钮"}).click({jitter: true});
await device.element({text: "目标按钮"}).click({jitter: false});
await device.element({text: "目标按钮"}).longPress({durationMs: 800, jitter: true});
await device.element({resourceId: "com.example.app:id/toggle"}).setChecked(true, {jitter: true});
```

HTTP 的 `POST /api/node` 和 `POST /api/tasks` 支持 `clickOptions: {jitter: false}`；未提供时默认开启。SDK 保持唯一匹配、过期目标验证和开关状态回读。触摸回执包含 `jitter` 和实际手机坐标 `point: {x, y}`；这些坐标尚未缩放为视频像素，动作效果仍以 `verification` 为准。

直接点击或拖动视频、输入框聚焦与文本替换不加入随机偏移：实时触屏转发的是浏览器收到的真实采样，改坐标就等于伪造用户没有做过的动作。`device.tap(x,y)`、`device.swipe(...)` 等明确指定坐标的手势**不改变落点**，但会按真机实测的时长与速度曲线合成轨迹，可用 `realism` 选择合成方式（见下节）。设置开关时若已经达到期望状态，不发送触摸，也不会产生落点回执。

## 文字输入与结果确认

网页只保留一个草稿框。编辑、`fill/type`、Enter 换行都不会写入手机；只有点击“填写到手机（替换全文）”才执行一次操作。目标来自唯一的可编辑手机焦点，或使用者在下拉列表/元素树中的明确选择。不会猜测多个字段，也不会在焦点变化后自动把草稿发往新字段。

手机改字不会覆盖网页草稿。“读取当前内容”读取所选字段一次，替换草稿前会提示未发送内容；读取不会修改手机。原始键盘、剪贴板和额外手势放在高级操作中。原始按键仍可能经过 IME，其回执只表示已发送，不证明应用接受。

网页按钮与 JS `element.setText(text)` 共用一次写入、原目标回读验证。不需要手动绑定、不轮询同步、不根据手机新内容自动改写草稿，也不在填写后发送 Enter/Tab 或点击业务提交按钮。

剪贴板“粘贴”需要当前手机有唯一可编辑焦点；`setText` 则定位明确选择的可编辑节点，不要求先用屏幕键盘逐字输入。应用首页的搜索入口可能只负责打开搜索页，不能当作输入框填写。使用 JS 面板时，在代码框填写脚本并点击“运行脚本”即可由后端执行，不要求智能体具备浏览器 JavaScript 执行工具。

- 写入前窗口、目标身份或边界不匹配：拒绝操作，重新选择目标后再填写。
- 写入后原目标文字一致：返回 `verification=verified`。写后重新检查同一窗口、节点身份、父节点、包名和资源，再唯一定位回读；清空按钮等引起的局部尺寸变化可正常验证，显著位置变化或匹配歧义不会放宽。验证码自动跳到下一格不单独构成失败。
- 写入后文字不同：报 `TEXT_VERIFY_FAILED`，回执包含 `execution=sent`、`verification=failed`。
- 写入后窗口变化或原目标无法回读：报 `TEXT_RESULT_UNKNOWN`，回执包含 `execution=sent`、`verification=inconclusive`。先观察手机，不能当作未执行而直接重试。

以上两种写入后错误均会停止 JS 中未捕获错误的后续调用；网页保留草稿，不自动重试。更换视频通道或重连不会自动补发文字。

网页自己的写入已验证后，会用同一字段的最新快照更新填写目标，草稿保持原样。HTTP 回执先到、观察快照后到时，文字动作会暂时等待匹配的快照，最长十秒；不会重复写入。普通观察中的尺寸变化、其他字段取得焦点、换节点或换窗口仍需重新选择，不会自动跟随新目标。

`/api/binding` 和旧 `/api/text` 属于已移除的网页同步接口。一次写入使用 `/api/node` 的 `setText` 动作；按需读取使用 `POST /api/node/text`，参数为 `target`。公开 JS SDK 的 `element.setText()` 调用形式不变。

## 手机端与沉浸画面

布局由浏览器可用宽高决定，不按设备品牌、浏览器名称或是否支持触摸来区分手机与桌面。触屏车机、平板和手机横屏只要宽度足够，就显示完整工作区。

| 可用空间（网页像素） | 默认布局 |
| --- | --- |
| 宽度不超过 600 | 画面优先；点击“工具”打开应用、元素树、草稿、JS 与连接详情，再点击“返回手机画面”关闭 |
| 宽度 601–900 | 左侧保持完整手机画面，右侧窄工具区上下排列并滚动；不改成选项卡 |
| 宽度至少 901 | 保留完整双栏工作区；右侧应用与导航在上方，下方同时显示元素树、文字输入、JS 和时间线。面板按剩余高度分配，不滚动整个工作区；高度不超过 720 时文字输入与 JS 并排，时间线在其下方 |

手机顶部和底部控制栏合计约 64 像素，沉浸模式约 60 像素，另计设备安全区。常用导航使用短文字，保留完整可访问名称；通知栏和控制中心按钮位于右侧控制区，窄屏下从“工具”访问。竖屏、横屏及浏览器地址栏引起的视口变化都会重新适配，保持远程屏幕比例，不拉伸或自动裁掉边缘。桌面空间有限时在对应面板内查看长内容；窄工具区和手机工具抽屉可上下滚动查看全部功能。

说明、状态和操作条按文字换行后的实际高度排版，不用固定行高压缩内容。桌面面板标题保持可见，应用列表、节点列表、文字表单、编辑内容和时间线在各自区域内滚动；长内容不会把其他面板推到窗口外。文字读写按钮与结果状态、JS 运行按钮保持在各自编辑区下方；节点属性和文字说明较长时在自己的内容区查看。动作时间线使用 24 小时制，展开技术详情不会挤占时间列。

“沉浸画面”优先尝试让整个画面容器全屏；浏览器不支持或拒绝时，使用网页内沉浸布局，保留 DOM 触摸层和导航。iPhone 不要求支持元素全屏 API，浏览器栏可能仍可见。不会调用视频原生播放器全屏；视频保持 `playsinline`。视频通道兼容性仍取决于浏览器：仅 WSS 部署需要支持 H.264 WebCodecs，不能假定所有 iPhone 系统版本都支持。

沉浸模式也适用于车机、平板和手机横屏，可手动选择画面优先；退出后恢复对应宽高的工作区。手机、横屏、1024×600 与 1280×600 触屏工作区、1600×900 工作区均有本地布局回归测试；真实车机浏览器的安全区、字体及触摸命中仍可能存在差异。

## 网络中断与自动恢复

观察或控制 WebSocket 短暂中断时，页面显示“恢复连接”，暂停手机操作并释放未完成的触摸和按键，保留草稿与 JS 编辑内容。正在运行的操作脚本会停止，不自动续跑。已建立的视频通道尽量保留；恢复过程中视频可能继续更新，也可能停留在末帧，页面会明确提示控制暂不可用。

自动恢复只使用原页面、原登录和原连接身份，采用逐步延长间隔的重试，最多等待 60 秒。观察和控制两个通道都就绪后才恢复操作；旧通道和迟到的旧操作请求不会重放。恢复重试和心跳不会重置 5 分钟无操作计时。

其他页面接管、退出登录、登录失效、5 分钟无操作、服务重启或恢复超时都会结束原会话。旧页面不会自动抢回手机；点击“重新连接”属于明确的手动接管。服务重启或页面身份失效时需要刷新。浏览器后台冻结也可能超过恢复窗口，因此不保证长期后台保活。

应用审计记录通道打开、关闭码、关闭原因、恢复尝试及会话结束原因，不记录 WebSocket 查询中的连接令牌。HTTP 手机操作请求除页面、连接身份和 CSRF 外，还需要当前 `X-Console-Generation`；自动恢复更新该代号，上一代请求会被拒绝。

## 视频绘制与暂停恢复

支持主线程 `MediaStreamTrackProcessor` 和 Canvas 2D 的浏览器，直接读取 WebRTC 已解码的视频帧并绘制到 Canvas，不依赖原生视频元素的播放状态或帧回调。每次只读取和绘制当前帧，随后释放 `VideoFrame`；不增加解码帧队列、混帧或第二套编码/传输协议。手机旋转时按真实帧尺寸更新画面与触摸坐标。

浏览器缺少这些接口、Canvas 不可用或无法创建轨道读取器时，保留原生 `video` 播放器。回到前台或手机视频暂停结束后会再次尝试播放。WSS 仍使用 WebCodecs 解码和 Canvas 绘制，三种通道的优先级与并行策略保持一致。

电源状态未确认不等于视频暂停。网页在这种情况下显示“手机状态待确认 · 操作暂停”，继续展示已收到的画面，不自动发送唤醒命令；只有确认灭屏或锁屏时，点击画面才请求唤醒解锁。电源轮询通过独立轻量事件更新，即使状态未变化也更新采集时间，不依赖完整节点树刷新。连接恢复中同样不会因点击画面自动解锁。

“本页刚收到画面”和“本页末帧 N 秒前”记录本地绘制时间，不是手机采集到网页显示的完整延迟，也不能排除网络中积压的旧帧。状态待确认、锁屏暂停、连接恢复和等待首帧分别提示；不会仅因手机状态未知就声称画面已经停止。

WSS 将 Annex B 数据转换为带长度前缀的 AVC 帧，并给 `VideoDecoder` 提供明确的 SPS/PPS 配置。启动、配置改变及解码重置后等待实际 IDR 帧，不把预测帧改标成关键帧；重复的相同配置不重置解码器。关键帧解码错误最多在原连接内恢复一次，限频请求新的关键帧；恢复等待超过十二秒或再次失败时，进入现有通道重连流程。暂停期间不会为关键帧请求恢复视频发送。绘制队列只保留最新待绘制帧，关闭后迟到的位图会释放，不覆盖保留画面；视频时间戳保留，用于 WSS 自适应编码反馈。

WSS 失败与限次恢复上报直接打印到后端日志，不写数据库。诊断包含格式、关键帧标记、有限的 NAL 类型列表和恢复次数，不包含视频内容。只有成功送达后端的上报才有日志记录，因此日志不等于完整的浏览器控制台记录，也不能仅凭没有上报就认定没有错误。

“已连接”与“画面已更新”分别判断。暂停结束或页面回到前台后，30 秒仍没有新显示帧则重新建立视频；收到过首帧也不会永久跳过这个检查。若 WebRTC 的解码帧数持续增加，但画面超过 8 秒没有新显示帧，同样重建视频并按现有通道策略重试。正常灭屏/锁屏暂停、页面在后台，以及静止画面没有新的解码帧时，不触发这项停滞判断。视频新鲜度仍按真实绘制/呈现帧更新，控制连接独立恢复。

复制的“连接详情”包含 `renderer` 和 `rendererFallbackReason`：`track-processor-canvas` 表示直接绘制 WebRTC 解码帧，`html-video` 表示原生播放器，`webcodecs-bitmap-canvas` 表示 WSS。绘制失败、视频轨道结束和恢复超时进入现有失败/重试流程；手动“重新连接视频”仍可用。关闭或替换视频时取消读取、释放轨道并关闭旧 peer，旧帧不会覆盖新画面。

本地 `npm run test:video-renderer:browser` 使用两个真实 Chromium WebRTC peer 和合成 H.264 画面，验证像素变化、尺寸变化、暂停恢复、原生呈现停滞、接口降级及资源释放，不连接手机或生产控制台。这些验证不代替目标浏览器的停车状态实测，也不保证浏览器被系统限制或冻结时仍能播放。

右侧工作区按实际可用宽度安排节点与操作面板，不按浏览器名称或触屏能力判断是否使用手机布局。短视口不再把文字输入和 JS 编辑器二次横向拆分；填写目标位于输入标题栏，普通应用刷新状态不持续占行，进程诊断移至“更多工具”。宽度足够时固定面板、由编辑器与列表滚动；极窄或极短的工具区允许整体滚动，保证所有操作仍能到达。

## 直接触摸、拖拽与结果诊断

控制连接、手机状态、权限与视频坐标均已就绪时，在画面内第一次按下立即发送 DOWN，无需先点击聚焦或进入长按模式；实际按住多久就是多久，移动即拖拽。视频新鲜度是独立提示，不会因为解锁后尚未收到新帧而阻断输入。支持鼠标、触屏和两指操作，手机屏幕范围内的触摸用于远程操作，工具面板的滚动用于网页。直接坐标输入不添加随机偏移。

画面周围最多 20 个网页像素内、手机画面面板中已有的非控件区域，也可作为滑入起点。不增加可见留白，不缩小画面或覆盖导航按钮；可用范围随当前布局变化。起点位于按钮、链接、输入框等控件时，始终由原控件处理，不转成手机手势。

外侧按下只记录待确认状态，不向手机发事件、不接管键盘焦点。移动至少 8 个网页像素并进入实际画面后，从跨入的屏幕边缘发送 DOWN，再发送后续 MOVE 和 UP。等待滑入的时间不会成为手机长按；外侧轻点、微小晃动、沿边移动和起点超出范围的拖动均不发送手机触摸。进入前离开缓冲范围、页面失焦或坐标布局改变会放弃这次动作；进入后与普通画面拖动一致，松手在画面外也正常结束。触屏浏览器即使自动扩大按钮命中区域，也按触点坐标判断外侧起点。

移动保留网页收到的采样点，浏览器支持时读取 `getCoalescedEvents()` 的历史点；不支持时使用普通 MOVE。同一指针最多每 16 ms 转发一个点（更密的点对轨迹没有贡献，弱网下只是成本），约每 24 ms 发送一个短批次，每批最多 64 点；服务端未确认的采样积压时批量间隔退避到 48/72 ms。按下、抬手立即发送；抬手前先发送剩余移动点，微小拖动也保留终点。服务端把每批采样重采样到 4 ms 网格（单调三次插值，经过每一个真实采样点、不过冲），再按绝对截止时间表播放：一批跨越 24 ms 的采样就用 24 ms 播完，**不再压缩**。多指采样按相对时间排序、按时间合并注入。不承诺复原浏览器或远程桌面已经丢弃的采样；不保证端到端时延固定。注入跟不上时回执会带 `compressedMs`，不静默。

- 网页焦点改变只释放键盘，不抬起正在拖动的触摸；切到后台、窗口失焦、捕获中断会取消手势。
- 手势期间固定坐标映射，暂缓视频通道自动升级、布局调整和背景 UI/应用观察；锁屏及断连检查仍保留。若旋转或视口实际变化，取消并释放旧手势，不把旧坐标映射到新画面。
- 触摸不与其他手机动作交错执行。其他动作正在执行时提示设备忙，不把一次按下积压到动作结束后再补放；拖拽期间也不能启动手机操作脚本。
- 控制采用有序 WebSocket 与手势序号。浏览器控制缓冲超过 128 KiB、未确认采样超过约 512 点或处理回执超时约 2 秒，会取消；服务端队列最多 256 点，排队超过约 1 秒也取消。按住期间每秒发送一次手势存活信号，不续期五分钟无操作期限；服务端五秒未收到手势通信时主动释放，避免网络中断后一直按着。重连后不重放旧手势。
- 视频尺寸改变、权限失效或序号不连续时，服务端主动释放已有触摸。手势取消按 ID 隔离，上一手势的延迟取消不会结束下一手势。

“连接详情”的 `input` 显示当前/最近手势的接收、发送、服务端处理采样数、序号、排队时间和取消原因。回执仍是 `verification=not_verified`：服务端已把事件交给手机控制通道，不代表目标应用一定接受，更不代表验证控件一定通过。视频新鲜度与控制链路诊断是独立指标。

回归包括合成页面中的四边滑入与边缘坐标、外侧轻点与微小移动、周边控件隔离、曲线、单像素拖动、焦点切换、原生触屏滑入与双指、竖横屏和全屏拒绝回退，以及模拟控制器的旋转释放、积压、会话替换。真实 iPhone 与 Muse 的远程桌面入口仍需结合实际浏览器版本和事件记录验证；若入口没有向网页传递 DOWN/MOVE，页面不能生成缺失的真实输入。

## 手势的合成方式

脚本、Agent 和网页“更多手势”按钮发出的手势不是真手指，形状需要单独决定。两类手势的目标不同，处理也不同。

**实时触屏**：几何坐标完全不动，只修时间轴。浏览器按上面的规则抽稀并批量发送，服务端重采样到 4 ms 网格后按真实间隔播放。设备端 `MotionEvent` 的 `eventTime` 由 scrcpy 服务端取**到达时刻**（控制协议没有时间戳字段），所以网络抖动会变成速度抖动，这一点无法消除，也不假装消除了。

**脚本/Agent 手势**：坐标由调用方给出，落点不变；时长与速度曲线按实测值合成——按压 65–119 ms（真机实测 70–108 ms），滑动走最小加加速度曲线，峰值速度落在全程 40–55%。

`realism` 选择由谁合成：

| 值 | 行为 |
|---|---|
| `auto`（默认） | 设备支持 `input pswipe` 时用端上合成，否则用客户端采样流 |
| `framework` | 端上合成：`input pswipe` 在 system_server 内生成整条时间线，全程一个 `downTime`、约 4 ms 采样批次。不支持时报 `UNREALISTIC_INPUT`，**不静默降级** |
| `client` | 客户端按 4 ms 网格生成采样后经 scrcpy 注入。任何设备可用。scrcpy 每个消息只发一个采样点，历史批次由系统输入通道按投递节奏合并产生——实测在这台设备上以 4 ms 注入时 `getHistorySize()` 多为 4 |
| `off` | 保持改造前的行为：20 段线性插值、固定按压时长 |

双指手势始终走客户端：端上合成目前只支持单指。取消手势时在**最后已发出的点**抬起，不会跳到终点。

## 受保护画面：已记录，暂不考虑 root

2026-10-11 记录：使用者反馈某些应用的登录页在手机上正常显示，但串流只显示标题栏，正文为黑色；使用者确认这是安全内容捕获限制。本轮没有在真实设备上复现或读取目标窗口标志。

Android 的 `FLAG_SECURE`、安全 Surface 等机制允许内容显示在物理屏幕上，同时从截图或非安全屏幕捕获输出中排除。标题栏可见、部分内容为黑色与这种行为相符；具体保护层仍需后续诊断确认。

目前保留以下边界：

- 暂不研究或实施 root、Hook、系统权限修改来解除保护。
- 更换 TURN/WSS 通道、调整编码或重连不能恢复在手机采集阶段已经被排除的内容。
- 视频连接正常与内容完整可见是两个不同状态；未来应在界面和观察 API 中明确提示受保护内容。
- UI 树可能仍可读取，但不能假设所有受保护页面都暴露节点；现有密码字段限制仍然有效。
- 仅靠黑色像素无法确认安全窗口，应结合窗口证据，证据不足时标记为未知。

后续可以评估只读窗口信息探测与状态提示。当前仅记录事项，没有加入探测、改变录屏行为或解除保护。

参考：[Android 安全窗口说明](https://developer.android.com/security/fraud-prevention/activities)、[scrcpy 上游受保护窗口说明](https://github.com/Genymobile/scrcpy/issues/3072)。
